# 后悔承诺门 · Harness（可执行版）

> 交付物：**单个 exe**，双击即可打开图形启动器；也可作为命令行工具跑 A–H 实验。
> 已实测：脱离仓库目录单独复制到任意空文件夹后仍可独立运行。

---

## 1. 目录里都有什么

```
regret-gate-harness/
├── regret-gate-harness.exe     ← 主程序（双击 = 图形启动器，约 12 MB）
├── 使用说明.md                 ← 本文件
├── .env.example                ← 环境变量写法示例（不含任何真实密钥）
└── output/                     ← 首次运行后自动生成
    ├── report.md               ← 实验结果报告（每次 run 覆盖）
    ├── metrics.jsonl           ← 每次 run 一条指标
    ├── audit/<run_id>.jsonl    ← 每个 run 的不可变审计时间线
    ├── run.log                 ← 走启动器时：子进程完整输出
    ├── console.log             ← 走命令行时：本次运行完整输出（打包后无控制台，靠它排查）
    ├── selftest.json           ← 自检结论（可验证的落地证据）
    └── launcher_config.json    ← 启动器配置（仅勾选「记住密钥」时含密钥）
```

> **只看一个文件就够**：`output/report.md`。其余是过程与取证材料。

## 2. 最快上手（离线，不需要任何密钥）

1. 双击 `regret-gate-harness.exe` → 打开「后悔承诺门 · Harness 启动器 v1.0.0」窗口。
2. 提供方保持 `fake（离线桩）`。
3. 点 **离线自检** → 日志区出现 `SELFTEST_OK`，说明打包完整、机制链路可用。
4. 点 **开始实验** → 默认跑 A–H 全组 × 每组 20 任务。
5. 点 **打开产出目录** 查看 `output/report.md`。

> 离线模式**不访问网络**，产出由内置桩模型生成，用途是**验证机制链路与指标口径**，
> 不是模型能力结论。

## 3. 用真实 API 测实测效果

### 3.1 在启动器里填三个字段

| 字段 | 说明 |
|---|---|
| **提供方** | `openai`（OpenAI 兼容端点）或 `anthropic`（Claude） |
| **API 地址** | 选定提供方后自动预填；可改成你的兼容网关地址 |
| **API 密钥** | 粘贴密钥，默认圆点隐藏，可勾「显示」核对 |
| **模型名称** | 点 **获取模型列表** → 从 `/models` 拉候选后下拉选择（也可手填） |

填完点 **开始实验**。密钥默认**只在本次运行内使用**：通过环境变量传给子进程，
不进命令行、不进日志、不进审计。勾选「记住密钥」才会写入
`output/launcher_config.json`——共用机器上不建议勾。

「获取模型列表」失败时的排查顺序：地址要含 `/v1`（或以 `/v1` 结尾）→ 密钥是否正确 →
该网关是否提供 `/models`（部分自建网关没有，此时直接手填模型名即可）。

### 3.2 为什么建议先小规模试跑

真实 API 是花钱的。建议：

```powershell
# 先只跑 A、F 两组，每组 4 个任务，1 次重复 —— 约 16 次 run
.\regret-gate-harness.exe run --provider openai --base-url https://api.openai.com/v1 `
    --model gpt-4o-2024-08-06 --group A,F --limit 4 --runs 1
```

确认产出与费用可接受后，再放大到 `--group all --limit 20 --runs 3`。

## 4. 参数含义

| 参数 | 默认 | 说明 |
|---|---|---|
| `--group` | `all` | `A`–`H` 逗号分隔，或 `all`；`H` 自动展开为 H-none/H-weak/H-strong |
| `--limit` | 20 | **每组**任务数，按类别轮转取样（每类各取 1/4），不会只取到一个类别 |
| `--runs` | 1 | 每任务重复次数；真实实验建议 ≥3 |
| `--model` | — | 真实 provider **必填**，写死版本（如 `gpt-4o-2024-08-06`），不要用滚动别名 |
| `--out` | `<exe目录>/output` | 产出目录 |
| `--configs` | 内置 | 想改配置先用 `init` 导出：`regret-gate-harness.exe init --out mycfg` |

---

## 5. 安全开关（务必读）

- **执行器默认 dry-run**：`execute_shell` / `http_request` 只记录不真正执行，`write_file` 默认不落盘。
  所以「高危命令被拦截 / 被放行」这件事**不会真的动你的文件**。
  要真正落地写操作需改代码里的 `LocalExecutor(dry_run=False)`——发行版不提供该开关。
- **审核 Agent**：真实 provider 下用同一模型 + 不同 prompt/temperature 作兜底（§8.5）；
  有独立审核模型时可在 `configs/base.yaml` 替换。
- **审计不可变**：`output/audit/*.jsonl` 只追加不覆盖；`base_text` 与 `finalized_text` 都保留。

## 6. 结果怎么读（避免误读）

打开 `output/report.md`，注意三条：

1. **看第 0 节数据来源**：`provider=fake` 的报告只说明链路与口径；结论必须来自真实 API 运行。
2. **看 H5 的措辞**：样本里没有任何 `reject` 时，报告写**「无法测量」而不是「不成立」**——
   这是刻意的，把「没测到」写成「没效果」等于伪造结论。
3. **看第 9/10 节**：失败 run 与未成功 run 全部保留在分母；单 run API 调用 ≤10、审计 <5 MB 是硬约束。

离线运行用固定步长时钟，`latency_ms` **不代表真实性能**；真实延迟只能在真实 API 运行下测。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 双击没反应 | 看 `output/console.log` 或 `output/run.log`；或命令行跑 `selftest` |
| 获取模型列表失败 | 地址要含 `/v1`；检查密钥；网关不支持 `/models` 就直接手填模型名 |
| 真实 API 报 401/403 | 密钥错误或无权限；确认模型名在账号可用范围内 |
| 报告里还是 fake 数据 | 提供方没切到 openai/anthropic，或看的是旧 `metrics.jsonl`（换 `--out` 目录重跑） |
| 想改阈值/规则/任务集 | `init --out mycfg` 导出后 `--configs mycfg` 运行 |
| 杀毒软件报警 | PyInstaller 单文件包常见误报；可改 `--onedir` 重新打包，或对 exe 做签名 |

## 8. 从源码重新打包

```powershell
cd harness
py -3.12 -m PyInstaller --noconfirm --clean --distpath dist --workpath build regret_gate_harness.spec
Copy-Item packaging/使用说明.md, packaging/.env.example dist/regret-gate-harness/ -Force
```

打包后先跑 `selftest`（应得 exit 0 且 `output/selftest.json` 里 `ok: true`），
再跑小规模 `run` 确认 `configs/` 与 80 个任务被正确解包。
