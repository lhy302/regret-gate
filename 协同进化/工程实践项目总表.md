## 1. 决策门（最重要的一节）

**在动手任何 KV 相关工作之前，必须先跨过 G2 这道门。**

```
G2 = 测量「一次 KV 编辑对后缀 KV 的实际影响半径」
```

- **若影响半径 ≈ 整条后缀** → 局部重算无收益，**KV 方向应诚实结题**，
  资源转向 P1（提示词验证）与 P3（微调链路）。
- **若影响半径显著小于整条后缀** → P5–P10 全部解锁。

**为什么把它当门**：它是**纯测量**，成本最低、信息量最大。
跳过它直接做 P5–P10，等于在未知地基上盖楼，而且**违反本项目最核心的原则**
（`docs/后悔承诺门 · Harness 验证补充文档 v0.2.md` §0.3：无论结果如何都要给出可操作结论）。

## 4. 硬件与环境的硬约束（每个项目都要考虑）

| 约束 | 值 | 影响的项目 |
|---|---|---|
| **GPU 显存** | GTX 1050 Ti，**4 GB**，compute 6.1 | P3 只能 QLoRA；P10 需外部算力 |
| **prefill 速度** | 0.6B 极快 | ⚠️ **P1 与 P5 的墙钟收益可能小于噪声** |
| **`cmake`** | ❌ 不在 PATH | P5、P7 编译前必须补 |
| **`nvcc`** | ✅ 已有 | P5、P7 可编 CUDA |
| **huggingface.co** | ❌ 不可达 | 一律用 `HF_ENDPOINT=https://hf-mirror.com` |
| **`D:` 盘 SATA** | ⚠️ 接触不稳（已修） | 大文件落 D: 需注意；重要产物备份到 E: |
| **PowerShell** | 只有 5.1，无 pwsh | 含中文的 `.ps1` **必须存 UTF-8 带 BOM** |
| **Python 控制台** | GBK | 脚本输出中文需 `PYTHONIOENCODING=utf-8` |

### ⚠️ 一条必须记住的方法论约束

> **0.6B 上不要用墙钟/延迟作为"KV 手术有收益"的证据。**
> 0.6B 的 prefill 本来就快到毫秒级，省下的时间可能淹没在测量噪声里。
>
> **应当测量的是**：`prefill_tokens_saved`（确定性、可复现）
> 与**KV 一致性**（`seq_rm`+`seq_add` 后与完整重算的差异）。
> **墙钟收益留到更大模型或云算力上测。**

## 6. 禁止事项（每个项目开工前重读）

来自 `../docs/后悔承诺门 · Harness 构建规范 v1.0.md` §0 与本会话的实测教训：

1. ❌ **禁止把"没测到"写成"没效果"**（H5 的教训，见 `../接手摘要.md`）
2. ❌ **禁止引入近似算法**（近似注意力 / 插值补偿）——会让误差来源无法归因
3. ❌ **禁止在 0.6B 上用墙钟证明收益**（见 §4）
4. ❌ **禁止跳过 G2 直接做 P5–P10**
5. ❌ **禁止把 `FakeClient` 结果当作模型行为结论**（离线 H 组三档完全相同即为证据）
6. ❌ 含中文的 `.ps1` 必须 **UTF-8 带 BOM**；Python 中文输出必须设 `PYTHONIOENCODING`
7. ❌ 不要用 `git add .`（本仓库有 `.gitignore` 保护的敏感文件）

## 7. 本项目的"成功"如何定义

**不定义成"机制跑通了"，而定义成"给出了可操作的结论"。**

参照 `docs/后悔承诺门 · Harness 验证补充文档 v0.2.md` §0.3：

| 结果 | 结论 |
|---|---|
| P1 显示提示词带来显著降幅 | harness 侧有独立价值，后训练是放大器 |
| P1 显示降幅不显著 | harness 侧不是瓶颈，等模型能力或后训练 |
| G2 显示影响半径有界 | KV 局部编辑方向成立，解锁 P5–P10 |
| **G2 显示影响半径≈全量** | **KV 方向结题，如实报告** —— **这也是合格产出** |
| P9 显示推理轨迹纠错有效 | 前沿点名的空白被补上（最高价值产出） |

**任何一格都是合格交付。** 唯一不合格的是：**不做测量就下结论**。
