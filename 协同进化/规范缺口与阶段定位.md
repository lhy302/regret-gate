# 规范缺口与阶段定位

> 本文档记录一个必须先解决的问题：**你要做的事和现有规范是冲突的。**
> 这不是否决，而是流程问题。按本项目自己的规矩办，才能避免重蹈"结果被污染"的覆辙。

---

## 1. 冲突在哪（原文对照）

### 1.1 构建规范 v1.0 §0 十条铁律

| 铁律 | 原文 | 与你的计划的关系 |
|---|---|---|
| 铁律 2 | "**不做后训练，不微调**，不调用未公开模型接口。所有实验都在现有可调用模型上跑。" | ❌ 与"后训练微调"**直接冲突** |
| 铁律 3 | "**不做 KV cache 操作**。不碰 logits、不碰 hidden states、不碰 attention。只操作 messages 数组和字符串。" | ❌ 与"魔改成可修改 KV"**直接冲突** |
| 铁律 7 | "射程锁硬编码在栈层，不靠提示词" | ✅ 不冲突，harness 侧继续有效 |

### 1.2 v0.2 补充文档

| 章节 | 原文 | 关系 |

| §10 | "所有依赖 KV cache 操作与模型自发行为的机制，**移出本实验范围**，写入后续路线图" | "后续路线图" = 你正在做的这一阶段 |

## 2. 为什么这不算"违反规范"

规范自己给了出路：

1. **§9.3 用的是"推迟"，不是"禁止"** —— 推迟的东西到时间了就该做。
2. **§0.1 移出 KV 的理由是"托管 API 不暴露"** —— 而本阶段的**前提正是放弃托管 API、走本地推理**。前提变了，结论自然可以变。
3. **§10 明确说"写入后续路线图"** —— 你现在就在写这个路线图的落地版。

**所以流程上完全正当。但必须显式化**，因为：

- §11 自己声明"不是路线图、不是承诺、不是设计目标"。**直接从一份自我声明为"不是目标"的提纲动手，等于把假设当成了任务书。**
- v0.2 §0 开头就写："不移出去，实验会被污染"。**同理，不把新阶段显式独立出来，两个阶段会互相污染。**

## 3. 需要一份新规范（建议内容）

建议命名：**《协同进化 · KV 操作与后训练规范 v1.0》**（或你自己的命名）

至少要回答这 8 个问题：

### 3.1 阶段关系

- 本阶段与既有 A–H 实验是**并行、取代，还是前置**？
- 既有 harness 的四项机制（风险分级 / 尾部自审 / 独立审核 / 射程锁编辑）在本阶段是**保留、修改还是重新定义**？
- 既有 200 runs 离线结论是否仍然有效？（应该是有效的，但要写明"新阶段不改写旧结论"）

### 3.2 铁律的正式处置

铁律 2、3 不能"悄悄绕过"。三种正规做法：

1. **修订**：把铁律 2/3 改成"在 `harness/` 实验范围内有效；`协同进化/` 阶段另有铁律"
2. **豁免**：明确写"本阶段豁免铁律 2/3，理由是 ___"
3. **分册**：新规范自带一套铁律，声明适用范围

**推荐做法 1** —— 保留原铁律的历史完整性，同时给新阶段合法空间。

### 3.3 成功判据（最重要）

v0.2 §11 没有判据，因为它是假设性提纲。**但你要做实验就必须有判据**，否则会重犯本项目最忌讳的错误：**把"没测到"写成"没效果"**（见 §0 真实性边界里 H5 的教训）。

必须提前写死：

| 项 | 需要定什么 |
|---|---|
| KV 操作的有效性 | 什么指标？上下文一致性？输出偏差？编辑后 token 分布的 KL？阈值多少算"有效"？ |
| 后训练的收益 | 0.6B vs 4B、微调前 vs 微调后，四格对照的**最小可检测效应**是多少？要多少样本量？ |
| 同族放大的假设 | "同族同后训练后的收益对照"——**收益如何量化**？如果 4B 收益大于 0.6B，能推出什么？不能推出什么？ |
| 失败判据 | 什么结果会导致"此路不通"的结论？**必须允许证伪**，否则不是实验 |

### 3.4 范围边界

- 本阶段**不做**什么？（防止又一次范围蔓延）
- KV 操作的边界：是否允许改 attention / logits / hidden states？（铁律 3 原本禁止，现在开到什么程度？）
- 是否仍要求"可泛化到托管 API"？如果不要了，**要明确写出本阶段结论的适用范围仅限本地推理**。

### 3.5 与厂商协作的边界

你的动机之一是"让厂商看到潜力"。那么：

- 哪些结论是**可以对外呈现**的？（必须有真实性声明，参见 v0.2 §0 与 §11 的声明风格）
- **严禁**把"本地 0.6B 微调结果"表述成"厂商模型的后训练价值"。

### 3.6 数据来源与合规

- 微调数据从哪来？自造 / 回流 / 公开数据集？
- 若用 harness 的审计日志回流（`audit_logger` 的 JSONL），**是否涉及用户数据**？需不需要脱敏？

### 3.7 评测集

- 用哪套评测？既有 80 任务能不能复用？
- 需要**held-out**，不能拿训练数据评自己。

### 3.8 可复现性

- 铁律 10 要求"固定模型版本/采样参数/种子"。本阶段加了训练，还需固定：**数据版本、超参、随机种子、CUDA/cuDNN 版本、卡型**。
- 权重 hash 已记录（见 `版本与来源清单.md`），训练产物也要记 hash。

## 4. 我建议的最小落地动作

不要一次写一份大规范。**先写一页纸**，只要四样东西：

```
1. 阶段名 + 一句话目标
2. 铁律 2/3 的处置方式（选修订/豁免/分册）
3. 成功判据 + 失败判据（允许证伪）
4. 本阶段不做什么（范围上限）
```

有了这一页，后面所有实验才有解释框架。**没有这一页就开跑，等于把 §11 的假设直接当成已验证结论的温床** —— 而这正是 v0.2 全篇在防的事。

## 5. 一个诚实的提醒

`v0.2 §11` 的声明写得很清楚："**不是路线图，不是承诺，不是设计目标**"。这话不是客套，是作者（也就是你自己，在前一阶段）刻意留下的护栏 —— 因为当时**没有证据**支持继续投入。

现在的正确顺序是：

```
先看 A–H 离线结果支不支持继续
        ↓
（离线是 FakeClient，还不能下结论）
        ↓
真实 API 跑 A–H，看四项机制的真实降幅
        ↓
降幅显著 → §11 值得转正 → 写新规范 → 做本阶段
降幅不显著 → §0.3 自己说了"harness 侧不是瓶颈，得等模型能力或后训练" → 那本阶段反而更该做
```

**注意最后一句**：按 §0.3 自己的逻辑，**无论 A–H 结果如何，本阶段都值得做**（只是理由不同）。所以这不是"要不要做"的问题，而是"**先有解释框架，再做**"的问题。
