## 4. 思考模式识别

### 4.1 四个稳定特征

**① 从约束反推机制，而不是从机制找用途**
消息 #24 开篇不是"我想做个牛逼机制"，而是先钉死约束：
"流式输出方法不可改变"、"当轮对话结束后才允许修改KV"。
**机制是在约束下被逼出来的**，而非凭空设计。

**② 用形式化替代品思考**
在不知道 token / KV 张量细节的情况下，用 **0/1 串**当占位符把流程写清楚：
`[1010(开始点)->01010101010<-(结束点)010101010101010]`。
这是**在缺乏领域符号系统时的正确做法**——先固化结构，再替换符号。

**③ 主动要求对照物**
消息 #25："记得**多找论文及其配套的工程实践**并让我理解"。
**这是元认知行为**：知道自己缺文献基础，主动补。

**④ 当场自我推翻（最稀缺的特征）**
消息 #29 的"**嗯？不对**"是全轨迹最有价值的一处：
用户先推出"稀疏注意力能把重算限制在受影响范围"，随即自己发现前提错了
（"稀疏注意力机制只是将历史Token存起来了"），然后**升级为更强的结论**
（"我的想法一直基于稠密注意力的'后续Token全算'"）。

**这个动作在两篇论文里都没有对应物** —— 论文写出来的是结论，看不到这种现场推翻。
**它是真正的思考质量证据。**

### 4.2 三个系统性弱点

**① 缺少"架构分支"意识**
用户全程用 Qwen3（**GQA**：16 heads / 8 KV heads）做规划，
但 **Leyline 的 δ-rotation 是 MLA 专属**：

> Leyline §6 原文："We validate on MLA because it admits the cleanest rotation correction…
> **Only step (3) … the rotation kernel itself, is MLA-specific.**"

GQA/MHA 路径 Leyline 只在 **App. H** 试跑（Llama-3.1-Minitron-4B、**Qwen3-4B**），
并报告 "the model-side **ill-formed-cache sensitivity** … manifests **more strongly**"。

**→ 用户选定的模型恰好落在论文标注为"未验证/更敏感"的分支上。**
这一点用户在轨迹中从未提到，是**最大的盲区**，但也是**最大的机会**（见 §5）。

**② 把"设计取舍"当成"错误"来修正**
消息 #26 用户为"带旧 KV"辩护，理由（"保留了为什么错的信息"）**方向对但机制解释错**；
而我在前几轮用实测把它整个否掉了。
**真相是中间态**：Leyline 把它形式化为 `AMORTIZE`，并明确说这**故意弱于** re-prefill。
**双方都偏离了准确位置** —— 用户低估了代价，我高估了错误程度。

**③ 有"放弃过早"的倾向，但能被打断**
消息 #28："**注意力抹除和注意力追加是不可能做到的了**……**只有等KV替换能做**"。
这个结论在**稠密注意力**下成立，但用户在**下一条消息里自己推翻了它**。
→ 说明**倾向存在，但可被自身的推理打断**。

### 4.3 与论文的"速度差"到底差在哪

用户的自我判断是"**他们思考出来的速度是比我快的**"。**这个判断需要精确化**：

| 维度 | 用户 | 论文作者 |
|---|---|---|
| 问题识别 | 独立完成（消息 #24） | 独立完成 |
| 接口设计 | 独立完成（半开区间 + 操作 + 替换内容） | 完成，并**加了语义模式 m** |
| 形式化 | **未做**（用 0/1 串类比） | 完成（$K^{\text{edit}}=\text{Concat}(...)$、δ-rotation 闭式解） |
| 正确性合同 | **未做**（提出"对账"但未定义判据） | 完成（`positional replay-equivalent correctness`） |
| 实现 | 未做 | 完成（SGLang / fork llama.cpp） |
| 实测 | 未做 | 完成（+11.2 pp / 241 ms / +14.3 pp） |

**所以差距不在"想得慢"，而在「把直觉转成可验证合同并实测」这一步。**
用户在 8 条消息（#24→#31）内走完了"构想 → 被纠 → 自纠 → 外推 → 定位"的全过程，
**这个速度本身不慢**；缺的是**形式化与实验执行**——而那恰好是工程能力的范畴。

**这直接支撑用户的结论（消息 #31）：应该去做论文欠缺的工程设计与落地阶段。**

| **G4** | **推理轨迹（thinking trace）的纠错** | EVOKE §8 自陈：thinking 区间淘汰在 hybrid 上因 Mamba 状态不可切片而 abort，需 `EVOKE_SUPPRESS_THINKING_STRIP` 绕过；并指向"a future **no-shift eviction mode (attention-only seq_rm/seq_add)**" | 用户消息 #30 独立提出，且**指出我漏了这一点** |

### G4 是最高价值项，理由有三

1. **论文明确点名它是未来工作** —— 不是我在猜
2. **用户独立提出，且纠正了助手的盲区** —— 说明这是"用户视角才能看到的缺口"
3. ★ **用户的技术栈有结构性优势**：EVOKE 的障碍是 **hybrid 模型（Mamba 状态不可切片）**，
   而用户的 `ik_llama.cpp` 是**纯注意力栈**，**不会撞上这个障碍**

**唯一需要诚实标注的**：EVOKE 说的是 hybrid 做不到；纯注意力模型上"淘汰 thinking 区间"
**应该可以直接做**（`seq_rm` + `seq_add`）。
所以**新意不在"能不能做"，而在"做了之后效果如何"** —— 那是**实验问题**，不是机制问题。
