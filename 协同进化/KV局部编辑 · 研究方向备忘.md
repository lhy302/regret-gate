## 1. 一句话的问题定义

> **当一段已经写入 KV cache 的内容被局部修改（替换/删除/插入），
> 下游有多少缓存真正失效？能否把修正代价限制在"真正失效的那一部分"之内？**

这个问题的价值不在于"省算力"，而在于：
它在**稠密注意力下无解**（影响范围无界），
而在**稀疏注意力下第一次变成一个有边界、可测量的工程问题**。

---

## 2. 成本分层：先把话说准

| 层 | 操作 | 代价 | 稠密下影响范围 | 稀疏下影响范围 |
|---|---|---|---|---|
| **L-a** | 位置平移（`seq_add` 重做后缀 K 的 RoPE） | **低**（V 无位置编码，无需重做） | 整条后缀（但便宜） | 整条后缀（但便宜） |
| **L-b** | 重算后缀**隐藏状态** → 重算 K/V | **中** | **整条后缀** | **有界** |
| **L-c** | 重生成后缀**文本** | **高**（= 整段重写，收益归零） | 整条后缀 | 整条后缀 |

**要点**：
- 位置偏移只触发 L-a，**本来就不贵**。
- "注意力抹除/追加"贵在 **L-b**，因为它改变的是下游的**表示**，不是 KV 的位置。
- 稠密注意力下 L-b = 整条后缀，所以**局部重算无意义**——这才是"做不到"的真正原因。
- 稀疏注意力下 L-b **有界** → 局部重算第一次有意义。

---

## 3. 核心机制假设（本文的立论）

> **影响范围由注意力模式决定，不由编辑操作决定。**

- 稠密注意力：每个 query attend 全部历史 → 改一处 → 波及全部后缀 → L-b 无界。
- 稀疏注意力：每个 query 只 attend top-k → **一个历史位置只被少数 query 选中**
  → 删/改该位置 → **只波及"选过它的那些 query"** → L-b 有界。

**因此**：稀疏注意力**不是**让 KV 编辑"更快"，而是**把编辑的影响半径从无界变成有界**。
这是结构性差异，不是常数因子差异。

---

## 4. 用户提出的强化版假设：不止"重算便宜"，而且"可以消除坏 token 被再选中的可能"

原始设想（值得作为独立假设检验）：

> 基于稀疏注意力"重算成本低"的特性，**把后续 query 采样到坏 token 的可能性直接消掉**，
> 从而不只是修正、而是**阻止污染再次发生**。

**这个想法比"低成本重算"更进一步**：它把问题从"事后修正"变成"切断传播"。

**但有两个必须做的区分**：

| 做法 | 性质 | 风险 |
|---|---|---|
| **A. 重算受影响 query 的 KV** | 恢复一致性 | 无额外风险，但仍有重算量 |
| **B. 移除坏 token 并阻止其再被选中** | **改变模型行为** | ⚠️ 模型训练时该 token 在候选池里，硬移除 = 分布外 |

**B 的问题**：稀疏注意力的"选中"是**学出来的**。硬性阻止某个位置被选中，
等价于在推理时**改变了注意力分布的定义域**，模型没见过这种输入分布。
**它可能有效，但它是"改模型行为"，不是"修正缓存"** —— 必须与 A 分开测，
且必须报"是否引入新的输出偏差"。

> **建议**：把 A 作为主路径（正确性可证），把 B 作为**独立实验臂**（收益可能更大但需证伪）。

## 5. 三个我之前没讲、但你必须知道的技术约束

### 5.1 约束一：影响范围是**跨层传递闭包**，不是"直接选中集合"

稀疏注意力**每层各有自己的选择**。坏 token 的影响链条是：

```
层 0: query q 直接选中坏 token
        ↓ q 的隐藏状态改变
层 1: q 作为 K/V 参与，可能被另一批 query 选中
        ↓ 又改变它们的隐藏状态
层 2: 继续扩散 ...
```

**所以"受影响 query 集合" = 直接选中集合的「跨层传递闭包」**，
必须**逐层计算**，不能只看一层。

**好消息**：闭包是**逐层收窄还是放大**取决于具体机制，**这是可测量的**——
这正是研究方向 R1 要测的东西。

### 5.2 约束二：重算会改变选择本身 → 这是一个**不动点问题**，不是一趟扫描

隐藏状态是稀疏注意力**索引器（indexer）的输入**。
一旦你重算了某个 query 的隐藏状态：

```
重算隐藏状态  →  索引器打分改变  →  选中的 top-k 改变
    ↑                                      │
    └──────────  新的 K/V 又要重算  ←──────┘
```

**这是一个自洽性问题（不动点）**，不是单向流程。

**两条务实出路**：
- **保守路线**：**冻结选择**（用编辑前的选择集合），只重算隐藏状态。代价可控、可证伪，
  但结果与"从头重算"有偏差 —— **偏差大小可测**。
- **精确路线**：迭代到不动点。代价不可控（可能不收敛），**不建议作为主路径**。

**这一点现有文献里我没看到有人处理** —— **它是真正的空白点。**

### 5.3 约束三：未来 query 的"是否选中"在编辑时**未知**

对**已生成**的 token，可以精确统计"谁选中了坏 token"。
但对**尚未生成**的 token，**你无法预知它们会不会选中它**。

**后果**：**中途修正的收益是事后才知道的**，不能事前精确规划。
这要求实验设计里必须区分：
- **离线可测量的影响半径**（对已生成部分）
- **在线不可预知的部分**（对未来部分）

## 6. 一个被低估的类比：这本质上是**缓存一致性问题**

用户提到"稀疏注意力像 CPU 的缓存与内存"。这个类比**比设想的更准**，
因为 **cache coherence（缓存一致性）正是"局部修改导致缓存失效"的成熟解**：

| CPU 缓存 | KV 编辑 |
|---|---|
| 缓存行（cache line） | KV 块 / 稀疏块 |
| 写失效（write-invalidate） | 删除该位置的 KV |
| 写更新（write-update） | 就地替换该位置的 KV |
| 一致性协议（MESI…） | **缺失**：没有机制保证"编辑后各方视图一致" |
| 失效粒度（line size） | **可借鉴**：确定"编辑必须失效多大范围" |
| 伪共享（false sharing） | **可借鉴**：改一个 token 波及无关 block = 伪共享 |

**最值得借鉴的三点**：
1. **失效粒度（granularity）**：CPU 用缓存行而非单字节。KV 编辑也应定义**失效块**
   （对齐稀疏注意力的块划分），而不是逐 token。
2. **写失效 vs 写更新**：两种策略的取舍在 CPU 领域已被充分研究，可直接类比。
3. **伪共享**：稀疏块边界导致的"改 A 波及 B"，是典型的伪共享问题，有现成对策（padding / 对齐）。

**这是一个尚未被 KV cache 研究系统利用的框架。** 建议在开题里明确引用它。

## 7. 人类写作类比：有启发，但必须标注为**动机**而非**证据**

用户的观察：

> 人类写长文档不可能把所有文字纳入焦点，而是：
> **最近几个文字（强焦点）+ 周期性审视已写内容 + 最近文字强依赖曾经文字**
> 形成一个"写作时没直接激活、但会被周期性审视"的全局架构。

**这个观察是准的，而且和架构设计对得上**：

| 人类写作 | 对应机制 |
|---|---|
| 最近文字的强焦点 | 局部窗口注意力 / 稀疏选择 |
| 周期性回头审视 | **尾部强制自审**（v0.2 §0.2 的机制之一） |
| 未被激活但被挂着的全局结构 | 远距 KV（低选择概率但保留） |
| 发现错误后回头改 | **本机制要补的那一环** |

**但必须标注两点**：
1. **这是类比，不是证据。** 它说明"这套架构是合理的"，**不说明"它一定有效"**。
   在开题里应当写成 motivation，**不能写成 justification**。
2. **有一处不对称**：人能"改一句而不重想全文"，靠的是**分层的全局表示**（心里有一份提纲）。
   而当前 transformer **没有这份提纲** —— 所以改一处会波及下游。
   **这恰恰反过来说明**：若要模仿人类，需要的是**两级表示**，而不只是"更聪明的重算"。

**后一点是一个真正的架构级建议**：把"全局提纲"做成**显式的一小段可复用 KV**（类似 PIE 的 "note"），
使局部编辑不必波及全局。可参见 [Models Take Notes at Prefill](https://browse-export.arxiv.org/pdf/2606.17107) 的"note 主导"观察。

## 8. 关于"通用性"的判断：其实没有损失

用户认为这是"针对稀疏注意力模型的特殊优化，失去了通用性"。**这个判断偏保守**：

| 事实 | 含义 |
|---|---|
| DeepSeek-V3.2-Exp 用 DSA（细粒度稀疏） | 头部厂商已上 |
| DeepSeek-V4.1-Flash **MIT 开源**，附技术报告 **[待核]** | 有可拿到的基线 |
| NSA 强调 **natively trainable**（[ACL 2025](https://aclanthology.org/2025.acl-long.1126.pdf)） | 稀疏已是训练期标准做法 |
| SGLang 有 HiSparse 实现（[文档](https://docs.sglang.io/docs/advanced_features/hisparse_guide)） | 推理侧落地成熟 |

**结论**：稀疏注意力**正在变成默认配置**，不是小众分支。
针对它做的优化**不是失去通用性，而是对准了主战场**。

**唯一真实的限制**：稀疏必须**训练时原生引入**，不能后加。
所以本方向**必须有自己的基线模型**，不能靠现成稠密模型改。

## 9. 建议的研究路径（按"先测量后发明"排序）

| 编号 | 课题 | 类型 | 出口判据 |
|---|---|---|---|
| **R1** | **稀疏注意力下 KV 编辑的影响半径测量** | **测量** | 给出"一次编辑波及多少 query/层/块"的分布。**必须最先做** |
| **R2** | **有界重算**：只重算受影响闭包内的 query | 工程 | 与完整重算的偏差 < ε，且重算量显著下降 |
| **R3** | **稀疏索引的编辑一致性维护** | 工程 | 编辑后索引无悬空引用；重映射正确 |
| **R4** | **冻结选择 vs 迭代不动点**：偏差对比 | 测量 | 量化"冻结选择"的偏差代价；判断迭代是否收敛 |
| **R5** | **近似补偿的误差界** | 理论/工程 | ⚠️ 必须给出误差上界，否则污染实验 |
| **R6** | **两级表示**（显式"提纲"KV）使局部编辑不波及全局 | 架构 | 编辑影响半径显著缩小 |
| **R7** | **erratum 显式追加 + 局部手术组合** | 机制 | 组合显著优于两者单独 |

**R1 为什么必须最先**：它是测量，成本最低、信息量最大，
**且它的结果直接决定 R2–R7 是否值得投入**。
如果 R1 测出"影响半径其实接近整条后缀"（即稀疏度不足以约束传播），
那么整个方向应当**在 R1 阶段就诚实地结题**，而不是硬做下去。

**这正是 v0.2 §0.3 的正确用法：无论结果如何，都是可操作的结论。**

## 11. 结论

1. **方向是真实的**：稀疏注意力把 KV 局部编辑从"无解"变成"有界可测"。
2. **最有价值的产出是问题定义，不是机制**：
   "局部注意力被打破后，如何把修正代价限制在真正失效的范围内"。
3. **最佳类比是缓存一致性**，它提供了失效粒度、写失效/写更新、伪共享等成熟概念。
4. **人类写作类比是 motivation，不是 evidence**；它更重要的是指出了**两级表示**这个架构方向。
5. **通用性没有损失**：稀疏注意力正在成为默认配置。
6. **必须先读 Leyline 与 EVOKE**，确认边界后再谈创新点。
7. **R1（测量影响半径）应当最先做**，且它的结果**允许否定整个方向** —— 这是它最大的价值。
