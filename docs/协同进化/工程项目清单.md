> **影响范围由注意力模式决定，不由编辑操作决定。**

# P4 · G2：影响半径测量【决策门】

## 目标

回答一个问题：**一次 KV 编辑（删除/替换/插入）之后，后缀里到底有多少 token 的 KV 真正"失效"了？**

## 为什么是门

| 结果 | 后果 |
|---|---|
| 影响半径 ≈ 整条后缀 | **KV 局部编辑方向结题**，资源转向 P1/P3/P10 |
| 影响半径显著小于后缀 | **P5–P10 全部解锁** |
| 影响半径介于两者 | 需要按比例评估，可能只对长上下文任务有效 |

**任何一格都是合格产出**（v0.2 §0.3）。**唯一不合格的是不测就下结论。**

## 具体任务

### 4.1 定义"失效"的可操作判据
两个层次，**建议都测**：

| 判据 | 定义 | 优点 |
|---|---|---|
| **数值判据** | 编辑后重算的 KV 与"完整重新 prefill"的 KV，逐 token 差异 > ε 的位置 | 客观、可复现 |
| **注意力判据** | 编辑前后，每个 query 的 attention 分布变化 > δ 的位置 | 更贴近"是否真的影响了行为" |

**ε / δ 必须用 P2 标定的噪声底**作为下界。

### 4.2 建立基线
在 Qwen3-0.6B 上，对**不同编辑位置**（前段 / 中段 / 后段）与**不同编辑长度**（1 / 8 / 32 token）测量：
- 受影响 token 数 / 后缀总长 = **影响半径比例**
- 影响半径随编辑位置的变化（越靠前是否越大？）

### 4.3 分层测量（关键）
必须区分三种编辑：
| 编辑 | 预期 |
|---|---|
| **删除** | 位置补偿 `seq_add` 后可恢复 → 影响半径应**接近 0**（EVOKE §3.4 的"拓扑切割"） |
| **等长替换** | 位置不变，但内容变了 → 影响半径取决于语义依赖 |
| **变长替换 / 插入** | 位置平移 + 新内容 → 影响半径应最大 |

### 4.4 跨模型对照（可选但强烈建议）
在 Qwen3-0.6B（**GQA**）与另一个 **MLA** 模型上各测一次，
**直接对照 Leyline §6 说的 "GQA/MHA ill-formed-cache sensitivity manifests more strongly"** ——
**"更敏感"到底是多少？没人给过数字。给出这个数字本身就是贡献。**

## 交付物

- `experiments/influence_radius/`（测量脚本 + 结果 JSON）
- **一张图**：影响半径比例 vs 编辑位置 / 编辑长度 / 编辑类型
- 一份结论：方向是否解锁

## 验收判据

| 判据 | 通过条件 |
|---|---|
| D1 | 明确报告噪声底与 ε / δ 的标定过程 |
| D2 | 覆盖 3 种编辑 × ≥3 个位置 × ≥3 个长度 |
| D3 | 区分"数值判据"与"注意力判据"，两者都报 |
| D4 | 报告**分布**而非只报均值 |
| **D5** | **无论结果如何都给出明确的方向性结论（解锁 / 结题 / 条件性）** |

## 风险与陷阱

| 风险 | 应对 |
|---|---|
| 0.6B 太小，影响半径特征不具代表性 | 明确标注适用范围；必要时加一个更大模型对照 |
| 把浮点噪声当成真实影响 | 每次重测噪声底（P2 已实测为 0） |
| 只测一种编辑就下结论 | D2 强制三类型全覆盖 |
| **结果不利就改判据** | **ε / δ 必须事前标定** |

## 依赖

P2（需要可信的测量工具与噪声底）。

## 预估

2–3 天。

# P5 · `/kv/splice` 端点（ik_llama.cpp）

## 目标

在 `ik_llama.cpp` 的 server 上新增 KV 编辑端点，**v1 只实现等长替换**。

## 前置

- **G2 通过**
- `cmake` 补上（**当前不在 PATH**；E 盘备份有 `cmake.zip`）

## 具体任务

### 5.1 服务端（C++）
参照 `examples/server/server.cpp` 的 `handle_slots_erase`（L1019）/
`handle_slots_save`（L959）/ `handle_slots_restore`（L989）的写法新增 `handle_kv_splice`。

**执行序列（顺序不可换，见设计文档 §4.3）**：
```
① 校验（区间、长度、射程锁）
② 快照（llama_state_seq_get_data，用于回滚）
③ llama_kv_cache_seq_rm(seq, start, end)     ← 必须先删
④ 在 start 处 decode 新 token 序列            ← 在干净上下文里算新 KV
⑤ delta = new_len - (end-start)
   if delta != 0: llama_kv_cache_seq_add(seq, start+new_len, -1, delta)
⑥ llama_kv_cache_update()  → 让 K-shift/defrag 生效
⑦ 校验不变式 → 失败则回滚 + 标记 kv_op_failed
```

### 5.2 协议（见设计文档 §5.2）
```
POST /kv/splice
{ "seq_id":0, "start":128, "end":133, "new_tokens":[111,222],
  "mode":"equal_len", "request_id":"..." }

200 → { ok, n_tokens, l1_fingerprint, kv_l2_hash, applied }
422 → 违反不变式（附 INV 编号）
500 → 已回滚 + kv_op_failed
```

### 5.3 工具层
新增 `draft.kv_splice`（模型给**文本片段**，服务端用 `/tokenize` 映射成 token 区间）。
**权威存储必须是 token id 序列，不是字符串。**

## 交付物

- ik_llama.cpp 的 patch
- 端点自测脚本
- 协议文档（更新 `examples/server/README.md`）

## 验收判据

| 判据 | 通过条件 |
|---|---|
| E1 | **空手术 `splice(i,i,[])` 结果逐位不变**（INV-8） |
| E2 | 等长替换后与"完整重新 prefill"的 L2 差异 < ε |
| E3 | L1 对账（token id + 位置）**100% 通过** |
| E4 | 越界/长度不符/违反射程锁 → **拒绝且 KV 不变** |
| E5 | 手术失败时**整轮作废**，绝不带不一致 KV 继续生成 |
| **E6** | **若 E2 不达标，如实报告，不放宽 ε** |

## 风险与陷阱

- ❌ 先 `decode` 再 `seq_rm`（顺序反了 → 时间混乱）
- ❌ 用**闭区间**传 `seq_rm`（它是半开 `[p0,p1)`）
- ❌ 忘了 `llama_kv_cache_update()`
- ❌ 手术失败后继续生成
- ⚠️ 编译前确认走 **build-cuda** 而非 build-cpu

## 依赖

P4（G2）。

## 预估

3–5 天。

# P6 · harness 双端对账（token id 权威）

## 目标

把 harness 的客户端状态从"字符串"改为"**token id 序列**"，并与服务端做 L1 对账。

## 前置

P2（正确性套件）、P5（端点可用）

## 具体任务

### 6.1 改客户端权威
| 现状 | 目标 |
|---|---|
| 存字符串，下轮重新分词 | 存 **token id 序列**；字符串仅用于显示 |

**证据（本会话实测）**：`print(reslt)` → `print(result)` 看着像改一个字母，
实测却是 **4 token vs 3 token** —— **文本等长 ≠ token 等长**。

### 6.2 定义两层对账
| 层 | 对象 | 判据 |
|---|---|---|
| **L1（硬契约）** | token id 序列 + 每个 token 的位置 + 总长 | **必须精确相等** |
| **L2（诊断）** | KV 张量字节 | 不要求相等，记录 hash 用于排查漂移 |

### 6.3 失败即整轮作废
L1 不一致 → **丢弃本轮 + 标记事件**，绝不带不一致状态继续。

### 6.4 接审计日志
手术必须记事件（`kv_splice_applied` / `kv_op_failed`），
**"为什么错"走审计日志，不要塞进 KV**（设计文档 §12.6）。

## 交付物

- harness 改动（新工具 + token id 权威 + 对账断言）
- 审计事件类型定义
- 端到端测试

## 验收判据

| 判据 | 通过条件 |
|---|---|
| F1 | 真实模型上跑 K1 臂 **100 次，L1 对账 0 失败** |
| F2 | 故意构造 L1 不一致 → 能检测到且整轮作废 |
| F3 | 审计日志含完整"改了什么 / 为什么改" |
| F4 | 现有 **268 tests 仍全绿**（不得破坏既有功能） |

## 风险与陷阱

- ⚠️ 改客户端权威会**触及既有 `revision_stack`**（射程锁、`resolve_range` 三级匹配）——
  **必须保持既有语义不变**，只把底层表示从字符偏移换成 token 偏移
- ⚠️ **不要**把 KV 手术与既有 A–H 机制混在一起（无法归因）
- ⚠️ 现有 harness 是**字符串级**操作（v0.2 §9.2 的 `ctx_*`），
  KV 手术是**新增一层**，两者必须能**独立开关**

## 依赖

P2、P5

## 预估

3–5 天。

# P7 · GQA/MHA 旋转核

## 目标

把 Leyline 的 δ-rotation 从 **MLA 专属**推广到 **GQA/MHA**，并**量化 ill-formed-cache 敏感度**。

## 为什么这是真空白

Leyline §6 原文：

> "We validate on MLA because it admits the cleanest rotation correction…
> **Only step (3) … the rotation kernel itself, is MLA-specific.**"
>
> "**Extension to GQA and MHA.** RoPE's unitary-rotation algebra transfers to GQA and MHA…
> **the complication is that they fuse position throughout the full K tensor** rather than isolating
> it to a slice, so **the rotation must act across all $d_K$ dimensions per token**…
> the kernel runs end-to-end on Llama-3.1-Minitron-4B and **Qwen3-4B** without numeric issues,
> but the model-side **ill-formed-cache sensitivity** we documented on MLA
> **manifests more strongly** because **rotation acts on dimensions that also carry content**."

★ **"更敏感"是多少？论文没给数字。给出这个数字就是贡献。**

## 前置

- **G2 通过**
- 读 **Leyline App. H**（GQA/MHA 的代数与实机验证细节）
- 读 **Leyline App. K**（CacheBlend / EPIC 的核层映射）

## 具体任务

### 7.1 实现
- GQA/MHA 下 K **全维度**参与 RoPE → 旋转需作用于**全部 $d_K$ 维**
- 复用 llama.cpp 既有的 `seq_add`（它已按 RoPE 语义更新 K）
- **先用 P2 的套件验证数值一致性**，再上真实模型

### 7.2 量化敏感度（核心产出）
| 指标 | 定义 |
|---|---|
| **数值偏差** | 编辑后 vs 完整重算的 KV 差异（分 K / V） |
| **行为偏差** | 同一 prompt 下输出分布差异（KL 或 top-k 重合度） |
| **敏感度曲线** | 编辑长度 / 位置 → 偏差量级 |

### 7.3 可选：接入边界重算
Leyline 点名两篇可直接插进核层的工作：
- **CacheBlend**（动态高偏差 token 选择）
- **EPIC**（静态 chunk 边界重算）

**这正是"只重算受影响范围"的现成方案** —— Leyline 指了路但没做 GQA 版。

## 交付物

- GQA/MHA 旋转核实现
- **敏感度量化报告**（这是可发表的部分）
- 与 MLA 路径的对照

## 验收判据

| 判据 | 通过条件 |
|---|---|
| G1 | 数值上：编辑后 KV 与完整重算的差异 < ε（GQA 下） |
| G2 | **给出"敏感度比 MLA 高多少"的明确数字** |
| G3 | 覆盖 ≥2 个 GQA 模型（Qwen3-0.6B 与 Qwen3-4B） |
| **G4** | **若敏感度高到不可用，如实报告 —— 这也是结论** |

## 风险与陷阱

- ⚠️ GQA 下位置**融进全部 $d_K$ 维**，旋转会影响承载内容的维度 → 必须实测敏感度，不能假设可迁移
- ⚠️ 不要为了"跑通"而放宽 ε

## 依赖

P4（G2）、P5

## 预估

5–8 天。

# P9 · 推理轨迹纠错【最高价值】

## 目标

解决"**模型在思考过程中写错了，但流式输出下无法回头修改**"。

## 为什么价值最高

1. **EVOKE §8 明确点名这是未来工作**（不是我在猜）：
   > "Qwen 3.5's `<think>` trace is **stripped from the response but kept in the physical cache**.
   > Strict alignment **would evict the thinking range from attention**, but
   > `llama_memory_hybrid::seq_rm` **rejects partial tail rollback of the recurrent half** …
   > **so the session resets**."
   > "**A future no-shift eviction mode (attention-only `seq_rm`/`seq_add`, already in the fork)** …"
2. **用户独立提出**（消息 #30），并**纠正了助手的盲区**
3. ★ **技术栈有结构性优势**：EVOKE 的障碍是 **hybrid 模型（Mamba 状态不可切片）**，
   而 `ik_llama.cpp` 是**纯注意力栈**，**不会撞上这个障碍**

## ⚠️ 必须诚实标注
EVOKE 说的是 **hybrid 做不到**；纯注意力模型上"淘汰 thinking 区间"
**应该可以直接做**（`seq_rm` + `seq_add`）。
**所以新意不在"能不能做"，而在"做了之后效果如何"** —— 那是**实验问题**，不是机制问题。

## 前置

P4（G2）、P5（`/kv/splice`）、P6（对账）

## 具体任务

### 9.1 确认基线模型
需要一个**有 thinking 轨迹的纯注意力模型**（如 Qwen3 的 thinking 系列）。
⚠️ 确认它不是 hybrid（否则会复现 EVOKE 的障碍）。

### 9.2 实现 no-shift eviction
- 用 attention-only 的 `seq_rm` / `seq_add`
- **不动循环状态**（纯注意力栈下本来就没有）

### 9.3 实验设计
| 臂 | 处理 |
|---|---|
| T0 | 基线：完整 thinking 轨迹 |
| T1 | 淘汰 thinking 中的**错误区间** |
| T2 | 淘汰**整个** thinking 区间（对照） |
| T3 | 保留 thinking 但**重写**错误区间（P5 的 splice） |

**观察**：最终答案正确率、thinking 长度、是否出现重复/自相矛盾

## 交付物

- 实现 + 实验报告
- 结论：thinking 区间纠错是否有效，以及代价

## 验收判据

| 判据 | 通过条件 |
|---|---|
| I1 | 确认基线**不是 hybrid**（否则记录并说明为什么不适用） |
| I2 | T1 相对 T0 的**答案正确率**变化有统计意义或明确无差异 |
| I3 | 报告 thinking 长度与 token 成本变化 |
| **I4** | **若无效果，如实报告"该缺口在此规模上不可验证"** |

## 风险与陷阱

- ⚠️ 选错模型（hybrid）会直接复现 EVOKE 的失败 → **先确认架构**
- ⚠️ thinking 区间边界如何确定？需要明确规则（模型自报 / 特殊 token / 正则）
- ⚠️ 0.6B 的 thinking 能力可能太弱 → 可能需更大模型（受算力约束）

## 依赖

P4、P5、P6

## 预估

5–8 天（含模型选型）。

# P10 · 微调后对照实验

## 目标

## 前置

P3（闭环打通）**+ 算力决策**

## ⚠️ 算力现实
| 任务 | 4 GB 显存 |
|---|---|
| 0.6B QLoRA | ✅ 可 |
| **4B QLoRA** | ⚠️ 极限（需短序列 + 梯度累积） |

## 验收判据

| 判据 | 通过条件 |
|---|---|
| J1 | held-out 评测，不拿训练数据评自己 |
| J2 | 每组样本量足以检测预设的**最小可检测效应** |
